## TL;DR

Three-tier ML research platform with **two production deployments** (frontend + backend) wired through one GitHub monorepo. The frontend auto-deploys to Vercel on push to `origin/main`; the backend lives in a sibling git folder pushed to a HuggingFace Space.

| Layer | Stack | Hosted on | Auto-deploy from |
|---|---|---|---|
| Frontend | Vite + React 19, Tailwind 4, Framer Motion | **Vercel** | `origin/main` (GitHub) |
| Backend | FastAPI + PyTorch + Ultralytics YOLO + HuggingFace transformers | **HuggingFace Space** (Docker) | `hf/main` (manual push) |
| Optional legacy backend | Same FastAPI subset | Render.com (`backend/render.yaml`) | not actively used |

Live URLs:
- **Frontend (production):** https://ml-research-platform.vercel.app
- **Backend API:** https://feveroliang-ml-research-platform.hf.space
- **GitHub repo:** https://github.com/KobkoonCoding/ml-research-platform
- **HF Space:** https://huggingface.co/spaces/feveroliang/ml-research-platform

## Deployment topology

### 1. Frontend → Vercel (auto)

- **Vercel project:** `ml-research-platform` (id `prj_d6pZOJk2JEzUT5LjfR4CzVtDhuxg`)
- **Linked GitHub repo:** `KobkoonCoding/ml-research-platform`, branch `main`
- **Root directory:** `frontend/` (set via Vercel settings)
- **Framework preset:** Vite
- **Production domain:** `ml-research-platform.vercel.app` (set as the project's primary domain — every prod build auto-promotes to this alias, no manual alias-move needed)
- **Other aliases (auto):** `ml-research-platform-kobkooncodings-projects.vercel.app`, `ml-research-platform-git-main-*.vercel.app`
- **Web Analytics + Speed Insights:** enabled (see `src/App.jsx`)

#### How a frontend deploy actually flows

```
git push origin main
  └─> GitHub webhook fires
       └─> Vercel builds frontend/  (npm install, npm run build)
            └─> deploys to dpl_<id>
                 └─> auto-aliases to ml-research-platform.vercel.app
```

### 2. Backend → HuggingFace Space (manual push)

The backend lives in `hf-space/`, which is its **own git repo** with one remote:

```
[remote "hf"]
url = https://huggingface.co/spaces/feveroliang/ml-research-platform
```

#### Deploy workflow

```bash
cd hf-space
# work on master locally
git add .
git commit -m "..."
# IMPORTANT: HF Space deploys from `main`, not `master`
git push hf master:main
```

After push, HF rebuilds the Docker image (3–6 min) using `hf-space/Dockerfile`. The Space exposes port 7860, mapped publicly to `https://feveroliang-ml-research-platform.hf.space`.

> **HF auth:** push uses HF's git credential helper. If pushes fail with 403, the user needs to re-auth via `huggingface-cli login` or git credential manager.

#### Backend warmup

The FastAPI app supports lazy model loading. Call this after deploy to warm everything:

```bash
curl -X POST https://feveroliang-ml-research-platform.hf.space/models/warmup \
  -H "Content-Type: application/json" \
  -d '{"models":["imagenet","food","bird","xray","skin","brain","yolo","pose","general","titanic","heart","wine"]}'
```

### 3. Frontend ↔ Backend wiring

`frontend/.env` controls the API base URL:

```
# .env (committed, used at build time by Vercel)
VITE_API_URL=https://feveroliang-ml-research-platform.hf.space

# .env.local (developer machine only, for local dev)
VITE_API_URL=http://127.0.0.1:8000
```

If you ever change the HF Space name (or move backend off HF), update **only** `frontend/.env`, push, and Vercel rebuilds with the new endpoint baked in.

## Common tasks

### "Add a feature to the frontend"

1. Edit `frontend/src/...`
2. Verify locally: `cd frontend && npm run dev` (usually port 5173)
3. Use Claude Preview MCP server (`frontend` config in `.claude/launch.json`) for visual checks
4. `git add frontend/<files>`
5. `git commit -m "feat: ..."`
6. `git push origin main` → Vercel auto-deploys in ~60–90s

### "Add a backend endpoint"

1. Edit `hf-space/main.py` (and helpers as needed)
2. Test locally: `cd hf-space && uvicorn main:app --reload` (port 8000)
3. Update `frontend/src/...` to call it (use `API_BASE` from `frontend/src/lib/constants.js`)
4. **Two pushes** required:
   - `cd hf-space && git add . && git commit -m "..." && git push hf master:main`
   - `git add frontend/<files> && git commit -m "..." && git push origin main`

### "Regenerate the OG image"

```bash
python scripts/gen_og_image.py
git add frontend/public/og-image.png
git commit -m "chore: refresh og image"
git push origin main
```

### "Site says it deployed but I see old content"

1. Hard refresh (`Ctrl+Shift+R`) — browser cache is the most common cause
2. Check live bundle hash matches the latest deploy:
   ```bash
   curl -sL https://ml-research-platform.vercel.app/ | grep -oE 'index-[A-Za-z0-9]+\.js'
   ```
3. If the alias hasn't moved, check Vercel dashboard → Deployments → confirm production state. The primary domain is configured correctly so this shouldn't happen now, but historically it has.

## Architecture notes

### Frontend modules

| Path | Purpose |
|---|---|
| `/` | Landing page v2 — three.js scroll-story (particle morph net→cloud→crystal, loss-landscape terrain), dark theme force-applied. Engine lives in `frontend/src/components/landing/v2/`; three.js is lazy-loaded so other routes don't pay for it |
| `/legacy` | Frozen copy of the previous (Spline-based) landing, noindex. Tag `landing-v1` marks the last commit with it at `/` |
| `/forensic/*` | Module 1 — data forensic & cleaning lab |
| `/elm-studio/*` | Module 2 — ELM training studio |
| `/deep-learning/*` | Module 3 — AI Model Hub (image, medical, detection, tabular) |
| `/docs`, `/about` | static info pages |

The Module 3 hub currently has **9 live tasks + 3 coming-soon (tabular)**. Tabular has frontend wiring + form schemas done, with `status: 'coming-soon'` until backend is verified end-to-end.

### Backend module map

`hf-space/main.py` exposes four route groups, all with shared `_model_lock` for thread-safe lazy loading:

- `/category3/*` — image classification (ImageNet, Food-101, Birds-525)
- `/medical/*` — Chest X-ray (DenseNet + Grad-CAM/pseudo-CAM), Skin Lesion (ViT), Brain Tumor (ViT)
- `/detection/*` — YOLOv8 animals, pose estimation, general 80-class
- `/tabular/*` — LogReg/GBM trained at startup from CSVs in `sample_data/`

Heatmap strategy:
- CNN models (X-ray DenseNet) → Grad-CAM, with `?use_pseudo_cam=true` query param for ~3× faster gradient-free version
- ViT models (skin, brain) → attention rollout (always gradient-free, no toggle)

## Known limitations / by-design decisions

1. **Single backend instance**: session state lives in RAM. Scaling to multi-worker requires Redis. Out of scope for the demo.
2. **Session TTL = 6h**: stale sessions get lazy-evicted; user must re-upload. Acceptable for the demo's working sessions.
3. **YOLO weights gitignored**: `*.pt` files are downloaded by the Dockerfile at build time. Don't commit them to git — they bloat history.
4. **Landing page forces dark theme**: the three.js scene has a baked dark palette. The `useEffect` in `LandingPage.jsx` enforces `data-theme="dark"` and restores the user's chosen theme on unmount.
5. **Landing 3D asset regeneration**: `frontend/public/dev-portrait.png` (particle-portrait mask) is baked by `scripts/gen_dev_portrait.py` from a photo outside the repo. The loader shows once per session (`sessionStorage` key `nexus:intro-seen`).
